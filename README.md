# MoirAI Cloud

Landing page for MoirAI Cloud, makers of Synaptix™, the AI infrastructure
operating platform: compute, networking, storage, monitoring and AI-assisted
operations in one console, with operators approving every change.
Contact: support@moiraicloud.ai.

Plain HTML, CSS and JS with no libraries, so it runs on GitHub Pages as-is. The
same page ships as a WordPress theme.

## What's here

```
index.html          The site. Generated by build.ps1. Open it or serve it.
site.webmanifest    Web app manifest (icons, theme colour).
assets/images/      Logo crops, favicons, eye mark SVG, founder photos and the supplied originals.
src/                Sources the site is built from. Edit these, not index.html.
wordpress-theme/    The same site as an installable WordPress theme (PHP).
docs/WIREFRAME.md   The wireframe and visual system the page follows.
build.ps1           Rebuilds index.html and regenerates the theme.
.nojekyll           Tells GitHub Pages to serve assets/ verbatim.
```

## View it locally

Open `index.html` in a browser. For the fonts to load reliably, serve it over
HTTP rather than the `file://` protocol:

```bash
# Python 3
python -m http.server 8000
# then visit http://localhost:8000
```

## Host it on GitHub Pages

1. Create an empty repository on GitHub. Don't add a README, .gitignore or
   licence, so the first push doesn't conflict.
2. Push this folder to it (see below).
3. In the repo, go to **Settings > Pages**.
4. Under **Build and deployment**, set **Source** to *Deploy from a branch*, pick
   the `main` branch and the `/ (root)` folder, and save.
5. The site goes live at `https://<your-username>.github.io/<repo-name>/` within
   a minute or two.

The folder is already a git repository with its work committed on `main`, so
you only need to add the remote and push:

```bash
git remote add origin https://github.com/<your-username>/<repo-name>.git
git push -u origin main
```

`index.html` is at the repo root and every path in it is relative, so Pages
serves it as the home page with no extra configuration, including from a
`/<repo-name>/` sub-path. GitHub Pages is case-sensitive; every file reference
has been checked against the real file names. The largest file is the theme
screenshot (377 KB); the page itself is 207 KB with all CSS and JS inlined.

Once you know the live address, give `og:image` in `src/_head.html` the full URL
(for example `https://<your-username>.github.io/<repo-name>/assets/images/android-chrome-512x512.png`)
so link previews work everywhere, then rebuild and push.

To use a custom domain later, add it under **Settings > Pages > Custom domain**
and point the domain's DNS at GitHub as that page describes.

## Editing the site

`index.html` is generated with all CSS and JS inlined, so do not edit it by hand.
Edit the sources instead:

```
src/_head.html      <head> contents: title, meta, favicons, fonts, structured data
src/_body.html      Page markup and all visible copy, SVG icon sprite at the top
src/css/theme.css   All styles, by numbered section (colour tokens at the top)
src/js/main.js      All interaction, one labelled module per feature
```

Then rebuild:

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1
```

That regenerates `index.html`, and also rewrites `wordpress-theme/style.css`,
`wordpress-theme/front-page.php` and `wordpress-theme/assets/js/main.js` from the
same sources and mirrors `assets/images` into the theme, so both deliverables
stay in step. `functions.php` and `index.php` are edited in place.

The build stops if an em or en dash appears in the page copy, if a `<video>` tag
appears, or if any raster image other than the logo or the founder photos is
referenced. It also turns every ™ in text into a small superscript (Urbanist
draws it as a full-size "TM"); inside SVG `<text>` write `&#8482;` instead, and
wrap text in a `<span>` if a flex container holds a ™.

After a rebuild, commit and push to update the live site:

```bash
git add -A
git commit -m "Describe the change"
git push
```

## The WordPress theme

`wordpress-theme/` is a self-contained theme (`style.css`, `front-page.php`,
`functions.php`, `index.php`, `screenshot.png`, `assets/`). GitHub Pages ignores
it because Pages does not run PHP. To use it, copy the folder into a WordPress
install under `wp-content/themes/`, activate **MoirAI Cloud 2**, then set a
static front page under **Settings > Reading**.

In WordPress the contact form posts to `admin-post.php` (nonce and honeypot
checked) and emails the message with `wp_mail`. The address defaults to
support@moiraicloud.ai and can be changed under **Settings > General > MoirAI
contact email**. Make sure the host can send mail (an SMTP plugin is the usual
fix if it can't). Functions use the `moirai2_` prefix.

## Notes

- The static site has no server, so on GitHub Pages the form validates, shows a
  short loading state, then opens the visitor's email app addressed to
  support@moiraicloud.ai with the message filled in (`$LeadEmail` in
  `build.ps1`). The WordPress theme sends it for real.
- No video and no video stills anywhere. The only raster images are the logo
  and the two founder photos (lazy-loaded); every other visual is SVG, CSS or
  canvas.
- Colours were sampled from the supplied logo: ring cyan `#55D4E1`, ring middle
  `#3199CC`, wordmark and ring end `#004AAE`. The logo has no navy (its pupil is
  pure black), so `--ink` is `#050A14`. Tokens are at the top of
  `src/css/theme.css`.
- Fonts (Urbanist, JetBrains Mono) load from Google Fonts, so the live site
  needs an internet connection for the intended typography.
- Logo: `moirai2-logo-original.png` and `moirai2-favicon-original.png` are the
  supplied files, byte for byte. The page uses `logo-h41.png` / `logo-h82.png`,
  trimmed to the logo's visible area with original colours. `moirai-mark.svg`
  is a vector redraw of the eye used where the 83px favicon would blur.
- Demo UI (hero console, problem demo, hub answers, rack view, audit log,
  density visualizer, oversight scenarios) is labeled "Illustrative". Host
  names, pools, times and loads in it are made up.
- Motion respects `prefers-reduced-motion`: the custom cursor, magnetic pull,
  typing, packets, auto-cycling, the scroll-driven roadmap and reveals are off,
  and numbers show their final values. Content is never hidden if JS fails.
- Lighthouse was not run (this PC has no Node.js). Run it in Chrome DevTools once
  the site is live.

## Before launch

Every unverified detail is marked `[CONFIRM: ...]`. Search `src/_body.html` for
`CONFIRM`, replace each with the real answer (or delete the sentence), then run
`build.ps1`:

1. Synaptix™ CoS: the product name (the client site says "Synaptik™ Cell") and
   its availability status.
2. CoS density visualizer: the real overhead ratio. The model (VM = 2 work + 1
   overhead cell; CoS = 2 work cells + 1 shared overhead cell per host) is a
   placeholder.
3. Founder cards: a short bio and a one-line "why we're building this" quote
   for each founder (four placeholders, shown as dashed placeholder text).
4. Founder story: an HTML comment above the Founders section, not shown on the
   page.
5. Roadmap, Multi-Site Management: any public timing.
6. Insights: the date of "How to Replace VMware Infrastructure: A Phased Plan".
7. Insights preview card: read time per article.
8. FAQ: who can approve AI actions.
9. FAQ: the deployment model.
10. FAQ: where operational data and AI processing live.
11. FAQ: what migration support MoirAI Cloud provides.

The Insights summaries were written from the article titles; swap in the posts'
own excerpts if they differ.
